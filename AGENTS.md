# AGENTS.md

Real-time face recognition (Haar → MediaPipe 5-pt landmarks → ArcFace alignment → ONNX embedding → cosine matching), plus optional servo/stepper face tracking. Windows-oriented. For the full pipeline and control tables, read `README.md`; for deeper architecture notes, `CLAUDE.md`.

## Running

There is **no build, lint, or test suite** — every module is a standalone interactive OpenCV script. Run as a package module **from the repo root** (modules use relative imports and root-relative paths, so `python src/foo.py` fails):

```bash
python -m src.embed            # sanity-check ONNX model: [1,3,112,112] -> [1,512]
python -m src.enroll           # prompts for a name, captures samples, writes DB
python -m src.recognize        # live recognition
python -m src.recognize_track  # recognition + servo search/lock tracking
python -m src.face_lock --name <NAME> [--camera 1]   # multi-face labels, lock, expressions, blinks
python -m src.evaluate         # genuine/impostor sweep to pick a threshold
python -m mqtt_tracking.face_track_mqtt [--mode fixed|onboard] [--invert] [--width 1280 --height 720]
python -m mqtt_tracking.face_track_mqtt_vertical [--invert]   # tilt-only; needs dual firmware
python -m mqtt_tracking.mqtt_publisher               # camera-free MQTT smoke test
```

All scripts need a webcam and an opened GUI window; they cannot be verified headlessly. A local `.venv/` exists. Deps: `opencv-python mediapipe onnxruntime numpy pyserial` (+ `paho-mqtt` for `mqtt_tracking`).

## Hard requirements / gotchas

- `models/embedder_arcface.onnx` (~166 MB) is **git-ignored and must be supplied manually**. Everything past landmarks (`embed`, `enroll`, `recognize`, evaluation) fails without it. `models/haarcascade_frontalface_default.xml` is committed.
- `data/` (db, enroll crops, debug, `action_history.jsonl`) is git-ignored and generated by running the tools.
- Default threshold is `0.34`, `distance = 1 - cosine_similarity`; accept if `<= threshold`. Comments say it came from `evaluate.py` — rerun evaluation after enrolling people or changing model/alignment.

## Architecture facts that bite

- **`src/haar_5pt.py` is the shared core.** `Haar5ptDetector.detect()` / `detect_all()` and `align_face_5pt()` drive every later stage. Changes affect the whole pipeline.
  - Haar only *gates* detection (largest Haar box validates FaceMesh points); the returned box is rebuilt from the 5 keypoints, not taken from Haar.
  - Keypoint order is fixed `[left_eye, right_eye, nose, mouth_left, mouth_right]` and must match the ArcFace template in `_estimate_norm_5pt`.
  - The detector is **stateful** (box/keypoints EMA-smoothed, `smooth_alpha=0.80`). Reuse one instance per stream; don't share across unrelated images.
  - `max_mesh_faces=1` by default, so all scripts except `face_lock.py` are single-face. `detect()` is single-face + smoothed; `detect_all()` returns every confirmed face **unsmoothed** (used by `face_lock.py`).
- **Matching is duplicated, not shared.** `recognize.py` and `recognize_track.py` each define their own `load_db` / `Matcher` / `DEFAULT_THRESHOLD` — keep them in sync. `face_lock.py` imports from `recognize.py`.
- **DB format:** `data/db/face_db.npz` = one mean, re-normalized template per name; `face_db.json` = metadata only. Re-enrolling a name overwrites it. `data/enroll/<NAME>/*.jpg` are aligned 112×112 crops; `evaluate.py` re-embeds them directly (no re-alignment), so they must stay aligned.
- **`embed.py`:** aligned 112×112 **BGR** in → RGB, `(x-127.5)/128`, L2-normalized 512-D out; CPU provider only.
- **Lock constants differ per script** (`LOCK_MATCH_RADIUS` 150 in `face_lock.py` vs 120 in `recognize_track.py`; `LOCK_SWITCH_FRAMES` / `IMPOSTOR_DIST` only in `face_lock.py`). Don't assume they're shared.
- **Tracking MQTT variant** (`mqtt_tracking/`) reuses `Matcher`/`Sweeper`/constants from `recognize_track.py` but publishes via `MqttAngleController` (same `set_angle` interface as `ServoController`). Topics under `face_tracking/`. `face_track_mqtt_vertical.py` tracks the Y axis and imports its shared constants/`screen_size` from `face_track_mqtt.py`, publishing to `face_tracking/tilt/...`. Firmware sketches each sit in their own folder (Arduino merges all `.ino` in one folder): `esp8266_stepper_mqtt/` (pan), `esp8266_stepper_mqtt_vertical/` (tilt only), `esp8266_stepper_mqtt_dual/` (both), each with its own git-ignored `secrets.h`. See `mqtt_tracking/README.md`.
- **Servo serial** (`servo_control.py`): writes `"<angle>\n"` at 9600 baud (default `COM5`). Opening the port DTR-resets the ESP8266, so it waits `BOOT_SETTLE_S` (4 s) and retries writes. Firmware: `sketch_sep12a.ino`.
